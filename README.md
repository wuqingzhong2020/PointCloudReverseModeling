# ReverseModeling

点云逆向建模工程。当前工程代码位于 [ReverseModeling](ReverseModeling/README.md)，使用 CMake / C++20，唯一产品入口为 Qt 桌面程序 `ReverseModeler`，始终包含 GUI。

第三方库由使用者预先准备，通过 `CMAKE_PREFIX_PATH` 和标准 `find_package()` 接入，可来自 vcpkg 或其他编译方式，也可分布在不同安装目录。工程只声明所需库、版本和组件，不管理第三方库的编译、安装或发布。

每个包含 C++ 文件的目录维护一个同名 `.cmake`，通过 `RM_SOURCES` 和 `RM_HEARDERS` 分别追加源文件与头文件，每个文件单独一条 `list(APPEND ...)`。主程序入口 `ReverseModeling/main.cpp` 在主程序的 `CMakeLists.txt` 中单独追加。各程序的 `CMakeLists.txt` 组合公共及专用文件清单，设置头文件搜索目录和链接库；所有第三方库的 `find_package()` 集中在 `cmake/Dependencies.cmake`。

## 构建与运行

### 环境与依赖

当前 Windows 预设使用 CMake 3.25+、Visual Studio 2022 MSVC v143、x64 和 C++20。依赖库需与工具链、架构及 Debug/Release 运行库匹配：

| 依赖 | 用途 |
|---|---|
| Eigen3 | PCA 与线性代数 |
| PCL 1.15+，common/io | PCD 点云读取 |
| Qhull（qhullcpp / qhull_r） | 障碍物扫描点的封闭凸包包络 |
| OpenSSL 3，Crypto | CWRM v2 文件编解码；分发时包含匹配的 Crypto 运行库及其 Apache-2.0 许可证 |
| OCCT 8+ | 几何建模、显示及 STEP 交换 |
| Qt6 Core/Gui/Widgets | 桌面界面 |
| SARibbon 2.8.0+ | 顶部 Ribbon 功能区；本机包要求 Qt 6.11+ |
| Qt Advanced Docking System 4.5.0+（Qt6） | 工具窗口停靠、浮动、显隐与布局恢复 |
| nlohmann_json 3.11+ | JSON 数据契约 |
| Google Test | `ReverseServiceTests` 测试程序 |
| CPython / pybind11 | 产品内建 Python；采用 SDK 的 `CPython::Python` 和匹配的自由线程 ABI |
| Python / Jinja2（仅构建机） | `RmCommandGen` 生成参数描述类与文档，安装方法见命令框架指南 |

所有第三方包由 [Dependencies.cmake](cmake/Dependencies.cmake) 统一查找，系统线程通过 `Threads::Threads` 接入。库可由 vcpkg 或其他方式预先构建；本工程不负责下载或编译第三方库。

C++ 编译约束统一在 [CompilerOptions.cmake](cmake/CompilerOptions.cmake) 维护，所有项目目标调用 `rm_apply_compiler_options(目标名)`。MSVC 使用 `/W4`、标准一致性模式和标准预处理器，GCC/Clang 使用 `-Wall -Wextra -Wpedantic`；默认 `RM_WARNINGS_AS_ERRORS=ON`，项目告警会阻止编译。诊断时可用 `-DRM_WARNINGS_AS_ERRORS=OFF` 暂时降为普通告警，不应以此代替修复。

vcpkg 等 `find_package()` 导入库的头文件保持 `SYSTEM`，MSVC 通过 `/external:I` 与 `/external:W0` 忽略其内部告警，GCC/Clang 使用 `-isystem`；工程头文件仍正常检查。不要全局禁用告警编号或修改 SDK 来消除告警，工程自身调用过时 API 等问题仍需修正。

根 [CMakePresets.json](CMakePresets.json) 保留通用工具链设置。先执行 `python envBuild.py init`，再在未纳入 Git 的 `envBuild.local.ini` 中填写本机 SDK 的实际安装前缀 `dependencies.prefix_paths`，可每行填写一个前缀；填写安装根目录，而非 `bin` 子目录。工程和 SDK 可以放在各自选择的位置，无需采用固定盘符或目录结构。已有构建时 init 会采用缓存中的 SDK；已有本地配置不覆盖。

`envBuild.py` 入口使用 SDK 的 Python 3.15t 和标准库，无需 pip。下文的 `python` 应指向该解释器；也可使用其完整路径。命令代码生成器另需构建机 Jinja2 环境，见[命令框架指南](docs/命令框架与Python使用指南.md#4-构建依赖和生成)。CMake/CPack 从 PATH 或本地配置定位，CDB 仅 `debug` 启动命令需要，填写原生 `cdb.exe` 路径。脚本不下载或编译第三方 SDK。

### 命令行

在你克隆或解压工程的根目录（包含 `envBuild.py` 和 `CMakeLists.txt`）打开终端，无需进入 `pythonProject`。完整参数、配置文件写法和更多示例见 [envBuild 命令使用指南](docs/envBuild命令使用指南.md)：

```powershell
python envBuild.py -h
python envBuild.py init
python envBuild.py info
python envBuild.py compile release
python envBuild.py release
python envBuild.py packageAll release
```

| 命令 | 作用 |
|---|---|
| `info` / `init` | 查看环境 / 创建缺失的本地配置 |
| `compile [模式]` | 配置、编译并自动部署；默认编译主程序与单元测试，不运行测试 |
| `release` / `debug` | 直接运行 Release / 用 CDB 调试 Debug；均不编译 |
| `prepareRun [模式]` | 手动补部署 DLL、Qt 插件和 OCCT 资源，不编译 |
| `package [模式]` | 将已有主程序及依赖通过 CMake 安装规则打成 ZIP，不编译 |
| `packageAll [模式]` | 编译主程序、自动部署并打包 |
| `clean [类别] [模式]` | 默认仅清理编译产物；具体删除与保留范围见 `clean -h` |

模式支持 `release`、`debug`、`release_debug`，初始默认 Release。全部命令支持 `-h/--help`；空命令显示总帮助，输错命令或参数显示相关帮助并返回 2。有副作用的命令支持 `--dry-run`。`compile` 支持 `--target ReverseModeler` / `ReverseServiceTests`、`--jobs`、`--rebuild`、`--fresh`；更换 SDK 后需显式 `--fresh` 重建缓存。

中间文件位于 `build/vc143-cpp20/`，当前 Release 可执行文件位于 `output/vc143-cpp20/release/`。一般输出规则为 `output/<编译器>-cpp<标准>/<构建模式>/`，由 [common.cmake](cmake/common.cmake) 设置。

构建、测试和手工验证时留存的日志及配套诊断记录统一放在 `output/log/`，不散放在 `output/` 根目录；日志不提交 Git、不进入发布包。命令默认输出到终端，保存示例见 [命令使用指南](docs/envBuild命令使用指南.md#6-产物在哪怎样交付)。

程序启动后自动写入 `ReverseModeler-年月日-时分秒-毫秒-进程号.log`，包含 Qt 消息、工作台提示、命令及内部预览任务的时间、级别、线程、任务编号、参数、结果和耗时。每次启动独立文件，约 10 MiB 分卷，自动清理 30 天前的本程序运行日志；原 `commands.log` 继续保留。开发目录使用 `output/log/`；安装版或该目录不可写时使用 `%LOCALAPPDATA%/ReverseModeling/ReverseModeler/log/`，实际路径记录在启动日志中。

Windows 未处理异常、C++ `terminate`、Qt Fatal 和 `abort` 尽力生成同名前缀的 `-crash.txt`（原因、异常码、地址、线程）和 `-crash.dmp`。常规日志逐条刷新；崩溃处理不等待 GUI 或日志锁。强制结束进程、断电及部分系统快速失败无法保证进入处理器，转储也可能因资源损坏失败，结果写入诊断文本。崩溃文件不自动清理，排查时保留当次 `.log`、`-crash.txt`、`.dmp` 以及完全匹配的 EXE/PDB。Release 仍启用优化，同时生成 PDB 便于定位源码；无需将 PDB 放入最终安装包。

主程序正常构建后自动部署匹配配置的 DLL、Qt 插件、`qt.conf`、OCCT 资源和 SDK 许可材料，可直接双击 EXE。无需注入 SDK PATH，也无需再执行 `deployqt`（该命令已取消）。`prepareRun` 仅用于文件缺失、依赖更新等手动补部署场景；部署失败时编译命令会返回失败。运行中 EXE 被占用时先自行关闭程序，不会自动强杀进程。

```powershell
& './output/vc143-cpp20/release/ReverseModeler.exe'
& './output/vc143-cpp20/release/ReverseModeler.exe' -c help cloud.import
& './output/vc143-cpp20/release/ReverseModeler.exe' -f 'D:/data/建模.py' aa 'bb cc'
python envBuild.py prepareRun release
ctest --preset windows-release
python -m unittest discover -s tests/python -v
```

主程序启动支持 `--input_file 点云.pcd`、`--output_dir 输出目录`、`--record_file 录制.py`、`-c 命令 [参数...]`、`-f 脚本.py [参数...]` 和 `-h/--help`。只优先提取这三个指定的全局路径键，再解析 `-c/-f`；`--spacing` 等业务参数保留。指定输出目录后，顶部“导出并退出”将完整模型交付为 `reserveModel.step` 和两字段 `result.json`，成功提交才退出；普通导出和关闭不标记成功。`-h/--help` 在终端打印用法后直接退出，不打开 GUI；`--record_file` 最先开始录制，已有文件直接覆盖并打印日志；启动路径会转换为命令写入脚本。`project.export_and_exit` 交付后保存录制并退出；其他 `-c/-f` 执行完保持工作台打开，脚本通过 `sys.argv[1:]` 读取参数。更多示例见[启动参数说明](docs/命令框架与Python使用指南.md#启动时执行命令或脚本)。

Google Test 的用例筛选见 [测试程序说明](tests/README.md)。测试目标也会部署自身运行库。

ZIP 和 SHA256 校验文件位于 `output/packages/`。发布包仅收集安装规则指定的主程序和运行环境，不包含测试程序、用户点云/模型和旧 EXE。解压后运行 `ReverseModeler/bin/ReverseModeler.exe`；Debug 包仅用于内部开发，包含主程序 PDB。

不使用 Python 时，同一套 CMake 规则仍可直接使用：

```powershell
cmake --preset vc143-cpp20 -DCMAKE_PREFIX_PATH="<SDK 安装前缀>"
cmake --build --preset windows-release
cmake --build build/vc143-cpp20 --config Release --target prepare_runtime
cmake --install build/vc143-cpp20 --config Release --prefix output/install/release
cpack --config build/vc143-cpp20/CPackConfig.cmake -C Release -G ZIP -B output/package-staging/manual-release
```

`cmake --install` 和直接 `cpack` 均不编译；已有主程序和匹配 SDK 必须可用。完整部署规则见 [Runtime.cmake](cmake/Runtime.cmake)，安装/打包规则见 [Packaging.cmake](cmake/Packaging.cmake)。

### Qt Creator

打开仓库根目录的 `CMakeLists.txt`，选择 `Windows / Qt desktop + Google Test / MSVC v143 / C++20` 预设，并在运行配置中选择 `ReverseModeler` 或 `ReverseServiceTests`。桌面程序使用默认本机部署配置；若部署步骤选中了 Application Manager，应在 **Deploy Settings** 中切换为默认部署或停用其安装步骤。

在 Qt Creator 的 **CMake → Initial Configuration（初始配置）** 中填写本机 SDK 的 `CMAKE_PREFIX_PATH`；自动生成的预设 Kit 若没有关联 Qt 版本，不要保留未展开的 `%{Qt:QT_INSTALL_PREFIX}`。Qt Creator 不读取 `envBuild.local.ini`，这里须填写同一 SDK 安装前缀。首次链接及默认增量构建均会检查部署；只构建主目标且未重新链接时，可构建 `prepare_runtime` 补齐运行文件。VS 多配置目录共用缓存，`--fresh` 会重新配置 Debug/Release 的共同构建信息。

在 **项目 → 构建设置** 中选择 `Debug` 或 `Release`，确认“构建的步骤”已启用，命令中的 `--config` 与所选模式一致；命令行预设分别为 `windows-debug`、`windows-release`。若出现 `No CMake configuration for build type "Debug" found`，先查看 **概要信息** 中本次 CMake 的原始错误；配置已经成功但 IDE 仍无构建目标时，执行 **构建 → 执行CMake** 重新加载工程信息。`QColor` 等 Clazy 警告是代码检查提示，应与 CMake 配置失败分别处理。

新增源码后若出现 `reverse::logging::*` 等未解析符号，先执行 **构建 → 执行CMake** 更新源码清单，再重新构建。若报 `C1041`、提示无法打开 `vc143.pdb`，先结束同一构建目录、同一配置下重复启动的构建，再保留一个入口构建；工程已为 MSVC 启用 `/FS` 来协调 PDB 写入，仍不要同时从 Qt Creator 和命令行编译同一目标。

调试输出中的 `0xe06d7363 ... (first chance)` 表示调试器先收到 C++ 异常通知，随后程序才执行异常处理，不能仅凭这条消息判断崩溃。`DWrite`、`UIAutomationCore` 表示异常来自 Windows 字体/无障碍组件；查看后续是否继续运行、是否出现未处理异常及崩溃日志。工程抛出的 `GeometryError` 会在命令服务边界转成失败结果，例如封板优化误选腹板时返回 `cap_invalid_connections`，应改选梁端肋板。Qt Creator 的 **首选项 → 调试器 → CDB** 可控制 C++ 异常断点和是否将异常加入问题列表；排查实际崩溃时保留未处理异常断点。详见 [Windows 异常通知机制](https://learn.microsoft.com/en-us/windows/win32/debug/debugger-exception-handling) 与 [Qt Creator CDB 设置](https://doc.qt.io/qtcreator/creator-preferences-debugger-cdb.html)。

## 桌面工作台

顶部 Ribbon 按文件、编辑、点云、重建、模型修改和工具分组，中央为三维视图，底部状态栏显示任务进度并提供取消入口。工具窗口保留 Visual Studio 的窄标题栏和底部标签形式，配色与主窗口统一为深蓝。窗口只有**自动隐藏（默认）**和**固定窗口**两种状态：模型树、重建参数、操作面板默认收在右侧，命令窗口、任务信息默认收在底部。右侧和底部使用常驻 Qt 标签栏，所有窗口标签始终保留原位；点击标签固定展开对应内容并高亮当前标签，移开鼠标或点击模型不收起。同侧窗口共用一个内容区，每侧最多显示一个窗口，侧边与底部可以同时展开。图钉手动将当前组收回边缘；没有独立关闭、浮动或“Unpin (Dock)”入口。展开时三维视图及其他固定面板为其让出空间，面板改宽/改高时同步调整，收起后恢复。模型树上方展示对象，下方展示所选对象的只读属性，共用一个窗口；可拖动内部分隔条调整比例。**窗口**菜单固定展开所选窗口，“全部自动隐藏”将它们收回边缘；固定到同侧的窗口共用内容区，收起只隐藏内容，不删除标签。手动收起及切换同侧窗口保留编辑状态和内容，正常退出记忆布局；“恢复默认布局”恢复右侧和底部自动隐藏，不清空当前数据。点云、模型和参数仍只保存在本次运行的内存中。

模型树按实际部件展开，显示名称、颜色和板厚。生成或导入模型后自动切到 **可选：体**：左键点击三维部件会高亮整件、定位对应树节点并显示只读属性；点击树节点也会高亮对应部件。属性包含部件 ID、板厚及依据、网格包围盒和来源等，尺寸统一为 mm；导入 STEP/CWRM 没有板厚信息时显示“未提供”。点击空白或按 Esc 清空部件选择；需要框选点云时切回 **可选：点**。选择过滤支持 **点 / 线 / 面 / 体**：单击分别选取模型真实顶点、拓扑边、完整几何面或整个部件，四种类型均支持批量选择：普通点击替换，Shift（或 Ctrl）点击追加，再点已选对象取消；工具条加选/减选同样适用。所有选中对象同时高亮，属性框显示类型、数量及各对象编号；切换拾取类型或按 Esc 清空选择。点模式下拖动仍框选点云，模型的三角网格细分线不作为可选边。画框后可左键拖动四边/四角调整大小，拖动框内部移动位置；松开后更新选中点，加选/减选也支持调整最近一次框。

选择 PCD 文件后直接按 **毫米 mm** 导入，不弹出单位确认窗口。打开菜单同时接受 STEP/STP、CWRM v2 BRep 模型：STEP 自动将声明单位换算为 mm，CWRM 按 mm 读取。模型导入保留实体和曲面几何及位置，采用浅灰实体与深色轮廓；不恢复文件内的点云或参数模板；等厚实体的板厚从几何主面自动计算，并显示数字标签。导出菜单支持当前点云 PCD、模型 STEP/CWRM，以及单独的“模型采样导出 (*.pcd)”。当前点云导出保存完整点云（含截取/删除结果），不是显示采样；模型采样点云不等于原始扫描数据。`file.convert` 支持 STEP/CWRM 互转和模型采样为 PCD，禁止任何 PCD 输入（包括 PCD 转 PCD），正常点云导入导出不受影响。

当前模板提供 **H型钢 / H型钢（默认）**（含筋板）、**T排 / T排（默认）** 和 **其他模型 / 俯视焊件**，桌面重建固定使用点云板件识别，不设建模方式选择或手动参数建模入口。H 型钢重建参数面板只保留端部突出容差、识别腹板孔和忽略小孔半径三项设置，采样/噪声/轮廓容差自动估计；不显示未接入的基础/高级识别参数、文件/点数信息、识别表格及模型摘要；板件厚度与依据可在模型树和属性面板查看。重建不自动镜像；需要补建另一侧时使用“模型调整 → 全部镜像补全”。STEP 导出可用；含识别孔或拟合轮廓的模型不套用矩形板件偏差公式。基准面支持三点/特征面设置、预览确认、正视以及点云剖视（偏移、反向）；命令可录制回放。移动、旋转支持实体变换及原位置预览。圆角/倒角按等厚板件的平面轮廓处理，板厚不变，支持跨部件多边、回车或按钮统一预览和应用，整批失败保持原模型；添加孔支持圆形/三角形过焊孔及圆形/矩形底边孔，具备底边选择、异步预览、应用和命令录制。模型调整中的“修改板厚”支持选中一个或多个等厚实体板件，读取实际板厚，保持中面并向两侧等量增减；回车或“预览”只看效果，“应用”才修改实体。修改后的板厚同步显示在模型树、属性及标签中，并支持撤销、重做、命令录制和 STEP 导出。“外扩板件轮廓”支持多个等厚板件在板面内等距外扩，保持板厚和封闭内孔，提供预览、对比原模型和应用；命令为 `model.expand_contour`。

在“可选：体”模式选中一个模型后右键，延长/截取/合并/分割到板只需再点选一个目标板，立即执行；框选切割端部在松开鼠标时执行；修复单个或全部板件孔洞点击即执行。这些操作不打开操作面板，不需要填写数值、预览或点击应用。菜单悬停显示操作前后示意图及文字说明，多选时单件操作禁用；修复全部不依赖当前选择。支持 Ctrl+Z 撤销、重做和命令录制。批量过焊孔使用参数面板完成底边选择、预览和应用。具体用法与适用边界见 [板件编辑说明](ReverseModeling/README.md#右键板件编辑)。

视图工具条中“点云”和“实体”的主按钮控制显隐，箭头展开显示模式菜单；未接入的模式保持禁用。“停止重建”只取消当前重建任务，导入、导出及偏差计算通过状态栏的“取消任务”取消。窗口显隐通过顶部功能区的“窗口”菜单管理。

“模型修改 → 选点建模”提供 **选点建模** 和 **选点生成障碍物**。前者依次选择点云点或模型特征点，用矩形、圆、多边形或多段矩形拉伸，支持添加与切除；可按底板、世界 Z、基准面或指定面确定方向。下一步调整尺寸并预览，应用后支持撤销与录制。后者先点选模型参考平面，再设置点云剖视并框选点云，按完整点云生成盒状障碍物，不显示板厚、不参与工件镜像。

**障碍物操作顺序**：新进入时参考面未选择；先左键点击模型上的平面，再点击第三步“请框选障碍物点云”，按住左键拖框后松开，检查绿色预览并应用。参考面用于过滤一侧点云，并确定障碍物的贴合面；默认剖视偏移 10 mm。障碍物点云被隐藏时，可减小偏移、反向或关闭剖视。各步骤旁的“?”提供说明；“×”清除参考面，退出恢复原来的剖视设置。

框选后分别显示完整点云的框选点数和剖视后可用点数。剖视后点云不足时，可直接点击“关闭剖视并预览”，保留原框选并使用其中全部点云；也可调整偏移或反向后自动重新预览。这里的最低点数是点云样本数，无需逐个点击三个点。灰色障碍物外壳属于模型，不代表当前仍显示对应点云；第三步框选时可点击视图工具栏“实体”隐藏模型，查看真正的彩色点云。重新选面和预览成功时自动显示模型。

黄色框选框与鼠标选区使用相同的物理像素坐标；宽视口、停靠面板展开及高 DPI 下不受 OCCT 二维视场边距影响。

“打开”下拉菜单提供 **最近打开文件**，按成功导入时间列出最近 10 个点云或模型文件，点击按相应格式直接重开。重复打开移到首位，记录在重启后保留；失效路径标注为“文件不存在”并禁用。“清空记录”只清除历史列表，不删除文件。

视图区右上角提供中文视图立方体，点击面切换前后、左右、上下视角，点击棱或角切换斜视角；立方体随相机旋转显示方向。其上方“底板面”按钮按当前模型或点云识别底板的法线正视，并将工件长轴横向放置、自动适合视图，仅改变相机。未得到板件识别结果或模型时该按钮禁用。

点击 **测量** 进入两点测量：依次左键点选可见模型表面或点云，显示总距离和 X/Y/Z 分量（mm，保留两位小数），轴向线分别为红、绿、蓝色。选定第一点后移动鼠标可预览第二点，第三次点击开始下一组；右键菜单“退出测量”、再次点击测量按钮或 Esc 退出。测量期间仍支持旋转、平移、缩放和视角切换。XYZ 是工程坐标轴方向的绝对坐标差，不随相机旋转；模型优先捕获鼠标周围 16 个逻辑像素内可见的真实顶点/边端点，橙色标记表示已吸附；超出范围回退到显示三角面交点。点云取当前显示采样中的实际点。结果写入命令窗口，仅用于观察，不修改模型、板厚或导出结果；重新加载数据、开始任务或隐藏测量对象后清除。

当前直接导入已有 PCD 进行板件重建，不提供扫描分段拼接或二维图像识别选区，因此不设“自动对齐”“拼接时去重”“2D 识别精度”及对应的“更多”菜单。前两项针对多段扫描数据的对齐与拼接，后一项控制二维图像识别的掩膜边界，都不是本工程的重建精度参数。

点云默认使用紫色到青色的高度渐变，沿 PCA 截面短轴区分不同高度，旋转视图不改变点的颜色。“点云”下拉菜单可切换到柔和青色的纯色显示。颜色用于观察层次，不代表已识别出具体部件；显示采样不改变原始点云或建模输入。

生成和导入的模型统一使用浅灰色哑光表面与深色拓扑轮廓；选中部件使用浅青填充、蓝色边框，板厚标签橙底白字。视口按显卡能力启用最高 8 倍 MSAA，减少斜边和高亮轮廓的像素锯齿。STEP/CWRM 导入的等厚板件同样自动显示板厚，双击数字标签即可修改，也可通过“模型调整 → 修改板厚”批量编辑；修改进入撤销/重做，重新导出后保留实际厚度。无法识别等厚主面的部件显示“未识别”，不使用包围盒尺寸代替板厚。默认显示当前视角可见侧的板厚标签（mm），背面及被模型遮蔽的标注隐藏，旋转到另一面时随视角切换；可通过“板厚”开关整体隐藏。侧板、肋板标签来自点云顶边宽度识别结果，显示到 0.1 mm。板厚标签、模型树、属性与板厚输入框统一保留一位小数，不追加“估算”提示。底板厚度取两块侧板原始识别厚度的最大值，表格依据显示“侧板最大值”；例如 20.1 mm 与 17.3 mm 取 20.1 mm。底板从观测面向背侧加厚，宽度夹在两侧翼板内侧面之间；翼板下沿贴合底板底面，肋板仍落在底板上表面。缺少任一侧板的可靠识别结果时仍标为“未识别”，仅保留观测面。识别值属于点云估计，不能直接等同于名义规格或计量验收结果。可见标签在重叠时错开并用引线关联，视图过密时可放大查看。

“端部突出容差”是建模中的独立选项，默认 **30 mm**：底板沿梁长方向超出两翼板共同端部且不超过容差时收齐，超出容差则保留并在日志提示；设为 0 可关闭端部收齐。各翼板保留独立识别长度，调整后需重新重建，原始点云不变。此选项与仍待接入的平板/竖板投影参数不同。

“撤销 / 重做 / 重置”共用最多 10 步工程历史，覆盖点云编辑、模型重建、部件删除及已确认基准面。重置恢复最近一次导入状态，并可撤销此次重置；新导入建立新历史边界。对应命令为 `project.undo`、`project.redo`、`project.reset`，录制时逐条追加，中途开始录制自动补写当前会话前序操作，保留可回放的撤销/重做分支。详细规则见[命令使用指南](docs/命令框架与Python使用指南.md#撤销重做重置与录制)。

当前识别面向俯视线扫的单侧、近似正交 H 型钢：两翼板及筋板独立估计板厚和高度，低于翼板的筋板也参与识别；短筋板与同站位的可见断带不统一拉满。连续可见顶边按自动容差拟合直线/圆弧；俯视可见的腹板圆孔及长圆孔支持自动识别和半径过滤，筋板上方可见的四分之一圆缺口保留；下方遮挡缺口和背面连接不凭先验补造。具体证据与边界见[俯视线扫优化说明](ReverseModeling/README.md#俯视线扫-h-型钢识别)。STEP 可同时包含已识别板件实体和未确定厚度的独立观测面，导出会分别核对数量。

运行环境需要匹配的 `SARibbonBar.dll`、`qtadvanceddocking-qt6.dll`；默认 SDK 的 Qt 为 6.11.2，不能混用参考平台的 Qt 6.8.4 DLL。快捷键：`Ctrl+O` 打开点云或模型、`Ctrl+P` 重建参数、`Ctrl+Shift+E` 导出 STEP、`F` 适合视图。

窗口生命周期、主题资源和后续功能接入约定见[桌面工作台开发说明](ReverseModeling/README.md#桌面工作台)。

### 全部镜像补全

重建参数不设“镜像对称”；点击“开始重建”按扫描结果生成，不自动补建对侧。需要对侧时，先选择目标工件的任意一个部件，再点击“模型调整 → 全部镜像补全”。自动选中与它相连的整组部件，仅补齐这一组，不带入其他独立工件或障碍物，无需逐件选择或预览。自动以本组已识别腹板的中面为镜像面；导入模型等没有已识别腹板的情况，从本组选择参考底板。参考板和已有对称部分保留，孔洞、圆角、板厚随镜像保留，Ctrl+Z 可整体撤销。“镜像补全”用于所选板件。

### 局部重建

已经重建后发现多余点云时，可先截取/删除点云，再切换“可选：体”选择需要修正的部件，点击“局部重建”。选择规则并预览，满意后应用。Shift 支持多选。只替换选中的部件，未选部件的几何、位置、板厚与 ID 保持不变；整批任一部件失败则不提交，原因输出到命令窗口。

- **平板（保持原板面）**：使用原板件关联的剩余点云拟合外轮廓，保留原方向和当前板厚，适合清理点云后的局部修正。
- **水平板（基准面方向）**：沿当前基准面法向；没有基准面时采用世界 Z。与该方向明显不符的点云会报错，避免把竖板压成水平板。
- **包围盒**：按当前模型的完整占用范围生成盒状障碍物，保留当前位置、方向及原包络余量；无需点云关联或轮廓参数，三方向须有有效跨度。
- 轮廓支持矩形、包络圆、倒角矩形、1/4孔角矩形、圆角矩形、凸多边形、任意多边形及连续曲线。倒角退距、角部半径和凹轮廓容差可调整；稀疏、分离或自交轮廓会明确报错。仅拟合外轮廓，不重新识别内孔。

倒角矩形、1/4孔角矩形、圆角矩形提供“镜像重建竖直板下边”，默认勾选。保持原板面方向重建竖直板时，补齐俯视扫描不可见的下部至原板底边，并将上角形状镜像到底角；取消勾选则仅按剩余点云范围重建、只处理上角，下边保持直角。水平板不受此选项影响。

预览不改模型、不录制；应用通过 `model.reconstruct_local` 命令执行，支持撤销、重做及脚本录制/回放。例如：

```text
model.reconstruct_local --parts '["web"]' --type plate --contour rectangle
```

“包围盒”将所选模型当前的完整占用范围重建为盒状障碍物，沿当前部件坐标系；不要求原始点云关联、板厚或轮廓参数，也适用于已有障碍物、移动后的模型和导入实体。每个选中对象分别成盒，只替换选中对象；原包络余量保留，结果不显示板厚、不参与全部镜像，可整体撤销。

平板类重建必须具备原始点云关联，导入 STEP/CWRM、手工新增或缺少支持点的部件不能使用平板规则。关联按首次重建时板面附近的原始点索引建立，后续只使用仍保留的点；已移动/旋转的部件须先撤销变换。选中部件已有的开孔、圆角或外扩等手工修改会由新轮廓替代，不影响未选部件。

### 障碍物重建

点击“开始重建”时，在 H 型钢、T 排或其他焊件板件之外，剩余有效扫描点会按空间邻近关系分组，并生成独立的“障碍物”避障包络。模型树可单独选中、移动或删除这些实体；STEP/CWRM 导出包含工件与障碍物，重建结果可整体撤销和重做。障碍物不显示板厚，不参与工件的“全部镜像补全”。包络包含扫描点及采样余量，用于保守避障；它不是未扫描背面的精确复原，孤立噪点不生成实体。

重建参数提供“钢板附近排除距离”，默认 **1 mm**，可在 0–1000 mm 内调整。按原始点到钢板表面的三维距离排除距离带内的点，超出部分继续参与识别，不因局部靠近钢板就删除整个物体。原始点云不改动，修改参数后重新点击“开始重建”；0 关闭这项距离过滤，扫描噪声和板边残差判定照常生效。H 型钢、T 排、其他模型共用此参数，录制回放会保存设置。命令示例：`model.reconstruct --obstacle-exclusion 1`。

针对相机略微斜视的扫描，H 型钢识别先以底板观测面和纵向顶边拟合工件坐标，障碍物阶段再拟合板端稀疏条带的实际方向，避免只按理想水平/竖直方向判断归属。条带仍须贴近已识别板边、具有足够的长度及窄的横向扫描支持；独立面、体和明显偏离板边的物体继续保留。这是基于几何证据的重建处理，不会猜测相机安装角并修改原始坐标，也不替代相机与扫描运动轴的标定补偿。
